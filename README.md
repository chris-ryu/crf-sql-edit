# crf-sql-edit

A small, headless command-line tool to **read and change the SQL inside ClipReport v5 `.crf` report templates** — no GUI Designer required.

It loads a `.crf` through the ClipReport engine's own public API
(`com.clipsoft.clipreport.base.Rexpert4`), lets you dump or replace the SQL of
individual datasets, and writes a valid `.crf` back out. Because it goes through
the engine, the binary REX file format and the field-level SQL encryption are
handled for you.

> Not affiliated with or endorsed by CLIPSOFT. This tool does **not** include any
> ClipReport software. You must supply the ClipReport v5 engine jars yourself from
> your own licensed installation (see Requirements).

## Requirements

- **Java 7+** runtime (to run) / JDK (only if you want to rebuild from source).
- **ClipReport v5 engine jars**, provided by you from a licensed install, e.g.:
  - `ClipReport5.0.<build>.jar`
  - `ClipReport5.0-Common.jar`

  Put them in a folder and pass it as the `-Lib` argument. These jars are
  proprietary and are intentionally **not** committed here.

A prebuilt `dist/crf-sql-edit.jar` (this tool's own compiled code) is included so
you don't need a JDK just to run it.

## Usage (Windows PowerShell)

```powershell
# point -Lib at the folder holding your ClipReport*.jar files
$lib = "C:\path\to\clipreport\lib"

# 1) inspect datasets and their current SQL
.\crf-sql.ps1 -Lib $lib list "report.crf"

# 2) export every dataset's SQL to editable .sql files
.\crf-sql.ps1 -Lib $lib dump "report.crf" ".\sql_out"

# 3) edit the .sql file(s), then write a NEW .crf with the changes
.\crf-sql.ps1 -Lib $lib set "report.crf" "report.new.crf" "DS1=.\sql_out\DS1.sql"
```

`set` accepts multiple datasets at once and also `Name.pre=<file>` /
`Name.post=<file>` for a dataset's Pre/Post SQL:

```powershell
.\crf-sql.ps1 -Lib $lib set "r.crf" "r.new.crf" `
  "DS1=.\sql_out\DS1.sql" "DS2=.\sql_out\DS2.sql" "DS1.pre=.\sql_out\DS1.pre.sql"
```

After writing, `set` re-reads the output file and verifies each change persisted,
printing `[VERIFY PASS]` or failing with a non-zero exit code.

### Running without the wrapper

```
java -Dfile.encoding=UTF-8 -cp "dist/crf-sql-edit.jar;<lib>/ClipReport5.0.<build>.jar;<lib>/ClipReport5.0-Common.jar" CrfSqlEdit list report.crf
```

(Use `:` instead of `;` for the classpath separator on macOS/Linux.)

## Build from source (optional)

```powershell
.\build.ps1 -Lib $lib      # compiles src\CrfSqlEdit.java -> dist\crf-sql-edit.jar
```

## Behaviour & caveats

- **The input `.crf` is never modified in place** — output always goes to the file
  you name.
- Only SQL-based datasets are touched. Stored-procedure / CSV / XML / JSON / SAP
  datasets are left as-is.
- The written file is re-serialized by the engine. In practice this means:
  - the file is saved in the current engine format (REX31) and **opens in the
    native Designer** (verified);
  - the dataset SQL is stored **in plain text** in the output (the engine reads it
    either way) — if you rely on the `.crf` keeping its SQL encrypted, this tool is
    not for you;
  - design-time preview thumbnails are regenerated by the Designer on next open;
  - the per-connection driver-jar hint (a Designer-only field) is not re-emitted —
    the server engine resolves the JDBC driver from its own classpath.
- Always open a changed report once in the Designer (or render it) before relying
  on it in production.
